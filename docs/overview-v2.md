# Air Alert Forecaster v2 overview

V2 adds live red/yellow maps, an hourly forecast for now, nightly data and model updates, and an optional news agent. Live display covers 139 polygons; the fixed forecast universe remains 119 units. The frozen [v1 report](report.md) records the earlier experiment. [Ingest evidence](ingest.md) and [frontend evidence](../web/IMPLEMENTATION.md) establish the current coverage.

## Data flow

Sources → ingest → records and episodes → as-of features → models → scheduler → API → UI. The CSV supplies history before the accepted cutover; a validated alerts.in.ua day archive repairs the outage and reconciles complete Kyiv days. siren.pp.ua supplies live observations, with an optional authenticated alerts.in.ua adapter. Ingest preserves source provenance, separates other hazards, and records when live inputs were observed. [Ingest](ingest.md)

Features use raw record prefixes, never future episode merging. Models estimate onset probabilities and remaining-duration quantiles. The scheduler polls live about every 60 seconds, issues forecasts hourly, and runs reconciliation, feature rebuilds, production refits and matured-outcome scoring at Kyiv midnight. Startup catches up a lagging ledger. FastAPI serves cached results to the black Svelte dashboard. [Onset and production](report-v2.md#production-behavior), [duration](duration-v2.md#production-hook), [scheduler](../src/airalert/scheduler.py), [UI](../web/IMPLEMENTATION.md)

The optional news worker stores observed message versions separately and uses the local Codex CLI to validate threat reports and propose bounded upward adjustments. It is off by default, never supplies labels, and has no measured predictive benefit. [News](news.md)

## What changed, and what remains

This table covers every constraint and limitation in the local v1 inventory, including its already-resolved audit items. Related items share a row. "Still open" on a design rule means the deliberate limit remains; it does not imply a defect. Evidence links point to publishable files because the local inventory is git-ignored.

| V1 constraint or limitation | V2 status | Current behavior and evidence |
|---|---|---|
| Strict hourly prefix, raw records versus merged episodes, deduplicated distinct-start counts | still open | Retained. Starts must precede the forecast hour; later ends are masked. Live observations must also precede it. [Contract](../AGENTS.md#hard-rule-the-as-of-contract), [v2 features](report-v2.md#source-shift-and-geography) |
| Inclusive duration-start boundary | still open | Retained at onset; remaining-duration features use the checkpoint's available record context. [Duration chronology](duration-v2.md#remaining-duration) |
| Fixed universe, oblast expansion and hromada-parent mapping; excluded permanent-alert regions | improved | Forecast geography stays fixed. Crimea, Luhansk and Sevastopol now have inherited live display, with no forecast. [Ingest](ingest.md#actual-live-handling) |
| Retrospective reporting-regime cutoff and two different source regimes | still open | The cutoff remains saved metadata, not an online detector. Per-horizon window comparisons and an archive-source flag expose the shift; they do not remove it. [Protocol](report-v2.md#protocol), [source shift](report-v2.md#source-shift-and-geography) |
| Original forecast-time splits and horizon embargo | improved | New validation and untouched test2 use the same outcome-maturity and embargo rules. [Split table](report-v2.md#protocol) |

The published served test2 BSS is 15.92%, 21.31% and 28.52% for 1/3/12 h, with pointwise 90% intervals in [bootstrap.json](../reports/v2/bootstrap.json). These scores describe the locked evaluation forecast, not the later production refit or news overlay. The server writes the rolling live track record nightly to git-ignored `reports/v2/track_record.json`. Once that runtime file exists, its scores appear in the report page's notes. Use [operations](operations.md) for running the service and [privacy](privacy.md) before publishing.
